# 日程調整 with 下野 — 設計書

日付: 2026-10-23
状態: 承認済み方針（ユーザー: 「1（Pages + Apps Script）で最後まで進めて」）

## 1. 目的と背景

下野（オーナー）の Google カレンダーから空き時間を自動抽出し、相手（家庭教師先の保護者など）がドラッグで枠を選んで申請できる、下野専用の日程調整サイト。

カレンダー上の予定はすべてが「絶対に外せない」わけではない。予定の種類（＝カレンダー）ごとに「外せない / 相談可」「前後バッファー」をオーナーが決め、◎○△× の記号と色で相手に提示する。

成功の姿:
- オーナーは相手ごとにリンクを作り、送る前に期間・時間帯・曜日・個別の枠を調整してから送れる。
- 相手はログイン不要で、スマホでも複数の枠を選んで申請できる。
- 申請はオーナーの Gmail に届き、ボタン一つで承認→カレンダー登録→相手に確定メール。

## 2. スコープ

### 第1段階（今回作る）
- 相手に届くページ（ゲストページ）
- オーナー専用の管理ページ
- 申請通知メール、承認・修正提案・却下
- カレンダーごとの記号・バッファー設定の編集

### 第2段階（今回は作らない。概要のみ §12）
- グループ日程調整（各メンバーが一度 Google 連携ボタンを押し、全員の空きを重ねる）

### 非目標 / アンチゴール
- 相手側に予定の中身（タイトル・場所・メモ・カレンダー名）が一切漏れてはならない。ゲスト向け API のレスポンスに記号以外を含めたら失敗。
- 相手にアカウント作成やログインを要求しない。
- 「AIっぽい」UI（グラデーション背景、丸いカードの多用、重い影）にしない。

## 3. 構成（決定事項）

| 層 | 技術 | 役割 |
|---|---|---|
| ゲストページ | GitHub Pages（静的 HTML/CSS/JS、ビルド不要） | 空き表示、ドラッグ選択、申請送信 |
| Apps Script（1プロジェクト） | デプロイ「public」（実行: オーナー、アクセス: 全員・匿名）と デプロイ「admin」（実行: オーナー、アクセス: **自分のみ**）の2つ | public: ゲストに記号付きの枠を返し、申請を受け付ける。admin: HtmlService で管理 UI を配信。Google ログイン必須は Google 側が強制する |
| データ | Google スプレッドシート（オーナー所有、1ファイル。`setup()` が作成し ID を Script Properties に保存） | 設定・リンク・上書き・申請を保存 |
| リポジトリ | GitHub `takos-mone/schedule-with-shimono`（公開） | 全コード。GAS は `clasp` で push |

**管理ページを GAS 側に置く理由:** ユーザー要件は「管理者ログインには Gmail ログインが必要」。アクセス「自分のみ」のデプロイなら Google 自身がログインとアカウント一致を強制するため、OAuth クライアント ID やトークン検証を自作せずに済む。

**1プロジェクト・2デプロイにする理由（レビュー後の変更）:** Web App のアクセス設定はバージョンの manifest から読まれるので、manifest を差し替えたバージョンをそれぞれのデプロイに割り当てる（`scripts/deploy.mjs` が自動で行う）。1プロジェクトなので Lock / Cache / Script Properties を共有でき、2プロジェクト間の競合が起きない。

**多層防御:** 両デプロイは同じコードを実行する。管理系の処理（予定の中身を返す関数、承認・却下、設定変更、管理画面の配信）はすべて冒頭で `isOwner_()`（`Session.getActiveUser().getEmail()` が `Session.getEffectiveUser().getEmail()` と一致）を確認し、一致しなければ拒否する。public デプロイ経由で匿名ユーザーが管理機能に到達しても中身は返らない。

秘密情報はリポジトリに含めない。スプレッドシート ID や Web App URL は gitignore 済みの `.env.local` からビルド時に注入する（公開 API の URL はゲストページに必要なので `docs/` 側の `config.js` に入るが、URL 自体は秘密ではない）。

## 4. 記号の定義と配色（決定事項）

配色は信号色（ユーザー選択 C）。

| 記号 | 意味（相手に表示する文言） | 色（背景/文字） |
|---|---|---|
| ◎ | 空いています | `#22a447` / `#fff` |
| ○ | 空き・前後に予定 | `#b8e35a` / `#2c4a05` |
| △ | 相談可・未定 | `#ff9f2e` / `#fff` |
| × | 不可 | `#ff6b5e` / `#fff` |

相手は ◎○△ を選べる。× は選べない。

## 5. 記号の自動判定ルール

### カレンダー設定（初期値、管理ページで編集可）

| カレンダー | 分類 | バッファー |
|---|---|---|
| 大学関連 | × | 30分 |
| バイト | × | 30分 |
| 部活 | × | 30分 |
| 遊び | × | 30分 |
| その他 | × | 30分 |
| メインカレンダー（オーナーのアドレス名のもの） | × | 30分 |
| 松尾研 深層学習 DL基礎講座 Autumn 2026 | △ | 30分 |
| 家族 | △ | 30分 |
| 日本の祝日 | 無視 | – |
| 他の人のアドレス名の共有カレンダー | 無視 | – |
| 日程調整（承認で作られる新カレンダー） | × | 30分 |

設定はカレンダー ID をキーに持ち、スプレッドシートに保存する。**カレンダー ID・メールアドレスはリポジトリ（公開）に書かない。** 初期値は `setup()` 実行時にカレンダー名で照合して作る（メインは `CalendarApp.getDefaultCalendar()`、他人のアドレス名カレンダーは ID が `@gmail.com` 等で終わりオーナーのものでないもの）。管理ページの設定画面で、オーナーのカレンダー一覧（`CalendarApp.getAllCalendars()`）を表示し、各カレンダーの分類（× / △ / 無視）とバッファー（分）を編集できる。一覧にあるが設定がないカレンダーは「×・30分」として扱う（安全側）。

### 判定アルゴリズム（1枠ごと）
優先順位の高い順に評価する。
1. 管理ページでの手動上書き（リンク単位）があればそれを使う。
2. ×分類の予定本体と重なる → ×
3. ×分類の予定のバッファー範囲と重なる → ×
4. 終日予定（「無視」分類のカレンダーを除く） → その日すべて ×
5. 承認待ちの申請（他リンク・同リンク問わず）と重なる → △
6. △分類の予定本体と重なる → △
7. △分類の予定のバッファー範囲と重なる → ○
8. それ以外 → ◎

補足:
- 自分が「不参加」と返答した予定は無視する。
- 枠の長さはリンクごとに 30分 または 60分。
- 時刻はすべて Asia/Tokyo。

## 6. リンク（相手ごとのページ）

オーナーは管理ページで相手ごとにリンクを作る。

リンクの属性:
- `id`: 推測不能なランダム文字列（22文字以上、URL セーフ）
- 相手の表示名（例: 山田さん（家庭教師））
- 期間（開始日〜終了日、最長 8 週間）
- 時間帯（例: 17:00〜22:00）
- 対象曜日
- 枠の長さ（30 / 60 分）
- 手動上書き: `{ 枠の開始時刻: 記号 }`
- 状態: 有効 / 停止

ゲスト URL: `https://takos-mone.github.io/schedule-with-shimono/?l=<id>`

**反映ルール（ユーザー決定）:** リンク発行後もカレンダーの変更は自動で反映し、手動上書きした枠だけ固定する。ゲストページは開くたびに最新を取得する。公開 API の計算結果は CacheService に 2 分キャッシュしてよい。

## 7. ゲストページ

- タイトル「日程調整 with 下野」（「下野」に黄色のマーカー）。副題に相手の表示名と期間。
- 週ごとの表示（‹ 前の週 / 次の週 ›）。縦軸は時間帯、横軸は曜日。
- 枠に記号と色を表示。凡例を上部に表示。
- ◎○△ の枠をドラッグで選択（同じ日の縦方向）。複数回ドラッグで複数範囲。選択済みをドラッグすると解除。マウスとタッチ両対応（Pointer Events）。
- 右側（スマホでは下）に「選んだ時間」を連続範囲ごとにまとめて表示。
- 入力: お名前（必須）、メールアドレス（必須）、ご用件（任意）。
- 「この時間で申請する」→ 完了表示。
- 停止中・存在しないリンクは「このリンクは現在使えません」と表示。
- デザイン: 白地、Noto Sans JP + 見出しに M PLUS Rounded 1c、黒の太枠、押せる感じのボタン。モックアップ `docs/mockups/admin-and-guest.html` の②に準拠。

## 8. 申請とメール

### 申請の受付（公開 API）
- サーバー側で再検証: リンクが有効、各枠が期間・時間帯・曜日内、各枠が現時点で × でない。× が含まれていたらエラーを返し、ゲストページに「選んだ時間の一部が埋まりました。もう一度選んでください」と表示して再取得。
- 1申請あたり最大 20 範囲。簡易スパム対策として非表示のおとり入力欄（埋まっていたら破棄）。
- 送信回数の上限: 1リンクにつき 1日 5 申請、全体で 1日 30 申請。超えたら「本日の申請上限に達しました」。
- ゲストページからの POST は `Content-Type: text/plain`（JSON 文字列を本文に入れる）で送る。`application/json` はプリフライトが発生し Apps Script が応答できないため。GET は `ContentService` の JSON をそのまま使う。
- 1 申請 = 複数の「範囲」（連続した枠をまとめたもの）。範囲ごとに状態（承認待ち / 承認 / 却下）を持つ。

### オーナーへの通知（Gmail）
件名: `【日程調整】山田さん（家庭教師）から 2件の申請`
本文（HTML）: 相手の名前・メール・用件、範囲ごとに日時と記号、各範囲に「承認」ボタン、申請全体に「修正を提案」「却下」ボタン、管理ページへのリンク。

メール末尾に「ボタンが開けない場合（複数の Google アカウントでログイン中など）は管理ページのリンク一覧から操作してください」と添える。

ボタンは管理 Web App（自分のみ）の URL へのリンク:
- 承認: `<admin>?action=approve&req=<id>&range=<n>` → 開いた時点で承認処理を実行し、結果を表示。冪等（承認済みなら「承認済みです」）。アクセスが「自分のみ」なので他人は実行できない。
- 修正を提案 / 却下: `<admin>?action=reply&req=<id>&type=modify|reject` → 文面入力フォームを表示し、送信で相手にメール。

### 範囲の意味（決定）
相手が選んだ範囲＝実際の予定の時間。メールの「承認」はその時間のまま登録する。管理ページから承認する場合は、開始・終了時刻を調整してから承認できる。

### 承認時の処理
1. 「日程調整」カレンダー（なければ作る）にイベント作成。タイトル `相手の名前：用件`（用件が空なら `相手の名前`）、説明に相手のメール。
2. 範囲の状態を「承認」に。
3. 相手に確定メール（件名 `【日程確定】下野との予定`、本文に確定日時）。

### 修正を提案 / 却下
- 承認待ちのまま 7 日経った範囲は、△の仮押さえとしては扱わない（状態は「承認待ち」のまま一覧に残る）。
- 同じ申請の中で一つの範囲を承認しても、他の範囲は承認待ちのまま（家庭教師の複数回分の申請を想定）。
- オーナーが入力した文面を相手にメールで送る。却下は該当範囲（指定がなければ申請内の承認待ち全範囲）を「却下」にし、△ の仮押さえを解除する。修正提案は状態を変えない（オーナーは必要なら別途却下する）。

## 9. 管理ページ

管理 Web App のトップ。3 タブ構成。

1. **リンク一覧**: 相手・期間・状態（申請 N 件未対応 / 確定済み / 停止中）。行を開くと申請の詳細と「承認」「修正を提案」「却下」ボタン（メールと同じ処理）。「編集」「リンクをコピー」「停止 / 再開」。
2. **リンク作成・編集**: 相手の名前、期間、時間帯、曜日、枠の長さ。グリッドには自動判定の記号に加えて予定のタイトルを表示し、枠をクリックすると予定の詳細（タイトル、時刻、場所、説明、カレンダー名）を表示（ユーザー要件: 管理側では中身をすべて見られる）。ブラシ（×でブロック / △ / ◎ / 自動に戻す）でドラッグ上書き。上書き枠には ● 印。「リンクを発行（保存）」。
3. **カレンダー設定**: §5 の表を編集。

## 10. データ（スプレッドシート）

シート:
- `settings`: key / value（JSON）。`calendarRules`、`ownerName`（下野）、`adminUrl`。
- `links`: id / name / startDate / endDate / dayStart / dayEnd / weekdays / slotMinutes / overrides(JSON) / active / createdAt
- `requests`: id / linkId / name / email / message / ranges(JSON: [{start,end,status,eventId}]) / createdAt

**書き込みの分担:** 1プロジェクトなので `LockService.getScriptLock()` で全書き込みを直列化できるが、念のため同じ行を両系統で書き換えない設計にする。
- `requests` は **1行 = 1範囲**（id / requestId / linkId / name / email / message / start / end / status / eventId / createdAt / decidedAt）。public は `appendRow` で追記するだけ。admin は自分の行の status 等のセルだけを更新する。
- `links` と `settings` は admin だけが書く。
- 全書き込みは `LockService.getScriptLock()` 内で行う。
- 書き込みのたびに Script Properties の `dataVersion` を更新する。ゲスト向けキャッシュのキーは `linkId + dataVersion`、TTL 2 分。これで上書き・承認・却下・新規申請は即反映、カレンダー自体の変更は最大 2 分遅れで反映。

## 11. 開発・デプロイ

```
schedule-with-shimono/
  docs/                 ← GitHub Pages 公開ルート（ゲストページ）
    index.html, app.js, style.css, config.js(生成)
  gas/                  ← Apps Script プロジェクト（clasp の rootDir）
    *.js, Admin.html, appsscript.json
  design/               ← 設計書・モックアップ（Pages には載らない）
  scripts/deploy.mjs    ← shared/slots.js を gas/ にコピーし、manifest を切り替えて public / admin の各デプロイを ID 固定で更新
  shared/slots.js       ← 判定・範囲まとめの純粋関数（GAS / ブラウザ / node テスト共通）
  test/                 ← node:test による純粋関数のテスト
```

オーナーに必要な手作業（Claude が代行できないもの）:
1. https://script.google.com/home/usersettings で「Google Apps Script API」をオンにする。
2. `clasp login` でブラウザ認可。
3. プロジェクトをエディタで開き `setup()` を一度実行して権限を許可（カレンダー、Gmail 送信、スプレッドシート）。Web App を開くだけでは同意画面が確実に出ないため。

デプロイは `clasp deploy -i <deploymentId>` で **既存のデプロイ ID を固定して更新** する。ID を指定しないと `/exec` の URL が変わり、`config.js` と送信済みメールのリンクが壊れる。デプロイ ID は `.env.local` に保存。

GitHub Pages は `main` ブランチの `/docs` から配信。

## 12. 第2段階（概要のみ）
グループ調整ページ。各メンバーが「Google 連携」ボタンを押すと、その人の予定の有無（busy/free のみ）を取得して全員の空きを重ねる。GAS の「アクセスしているユーザーとして実行」デプロイで実現可能だが、未審査アプリの警告画面が一度出る。本格化するなら Vercel 等＋Google Cloud OAuth（要審査）へ移行を検討。

## 13. ビルダー判断の一覧（ユーザーが確認すべきもの）
- 管理ページは GitHub Pages ではなく Apps Script（自分のみアクセス）で配信する。Apps Script は1プロジェクト・2デプロイ。
- 承認待ちの枠は他リンクで △ 表示。
- 承認した予定は新カレンダー「日程調整」に入り、×・30分扱い。
- 祝日は無視（終日 × にしない）。
- リンク期間は最長 8 週間。1申請最大 20 範囲。
- 「修正を提案」は申請の状態を変えない。
- 同じ申請の他の範囲は、一つ承認しても承認待ちのまま。承認待ちの△仮押さえは 7 日で自動的に外れる。
- 送信上限: 1リンク 1日 5 申請、全体 1日 30 申請。
- カレンダー ID・メールアドレスは公開リポジトリに書かず、スプレッドシートに保存する。

## 14. 運用開始後の変更（2026-10-24 時点、ユーザー確認済み）

- **編集画面**: Google カレンダーと同じ 0:00–24:00 の週表示。「相手に見せる時間帯」は相手に出す範囲だけを決める。予定ブロック・終日予定を押すと詳細（タイトル・カレンダー・扱い・バッファー・日時・場所・メモ）をポップアップ表示。
- **上書き**: ブラシ ×/△/○/◎/自動に戻す。「この週の上書きをリセット」「すべての上書きをリセット」（2回押しで実行）。
- **読み込み**: 予定は約10週間分を1回だけ取得し、記号はブラウザ側で計算。サーバー側キャッシュ5分、「↻ 最新にする」で再取得。カレンダー一覧は設定タブを開いたときだけ取得。
- **枠の長さ**: 15分 / 30分 / 1時間。15分のときは編集画面も15分行。
- **相手のフォーム**: 例文なし。「備考・コメント」欄（1000字）を追加し、通知メール・管理画面・カレンダー予定のメモに反映。
- **オーナー宛メール**: ボタンは「承認（複数日時なら すべて承認）」「修正を提案」「却下」の3つ。承認は申請内の全日時をまとめて登録し、相手への確定メールは1通。個別承認・時刻調整は管理画面から。旧形式の日時ごとの承認リンクも有効。
- **相手宛メール**: 確定・修正提案・却下のすべてに申請内容の表（日時と長さ・状態、ご用件、備考・コメント、お名前、申請日時）。確定メールの件名に日時とご用件を入れる。
- **過去の日程調整**: 「完了にする」（2回押し、リンクも停止）または「期間終了かつ未対応なし」で一覧から移動し、閲覧専用のログとして残す。手動完了は「一覧に戻す」で再開、期間終了分は「期間を延ばす」で一覧に戻る。
- **承認した予定の追加先**: リンクごとに自分が所有するマイカレンダーから選べる（既定は「日程調整」）。メール・管理画面どちらの承認でもそのカレンダーに登録。
